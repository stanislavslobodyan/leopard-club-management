# LEOPARD — система обліку комп’ютерного клубу

LEOPARD — Windows desktop-застосунок адміністратора клубу на C#, .NET, Avalonia UI та MVVM. Це робоча основа з локальними даними й адміністративними діями, а не попередньо заповнений сценарій: нова база порожня, і клуб вносить власний інвентар, тарифи та клієнтів.

## Можливості MVP

- Облік комп’ютерів із фактичними характеристиками CPU, GPU, RAM, монітора та накопичувача.
- Додавання клієнтів і тарифів.
- Початок, подовження та завершення сеансів із вибором ПК, клієнта, гри, тарифу й тривалості.
- Живі таймери, пошук і фільтри сеансів; перевірка конфліктів бронювання під час старту.
- Створення й скасування бронювань із перевіркою перетинів із бронюваннями та запланованими сеансами.
- Журнал завершених сеансів із розрахунковою сумою за фактичною тривалістю.
- Внутрішні сповіщення про 15 хвилин до кінця та про сплив часу.
- Програма лояльності: 1 бал за кожну повну годину завершеного сеансу.
- Компактна адаптація інтерфейсу для вузьких вікон і touch-доступного перегляду.

Оцінка суми в історії — це розрахунок за збереженим тарифом і фактичним часом. Вона не є касовим чеком і не підтверджує оплату. Бали нараховуються за час, а не за платіж.

## Передумови та запуск

- Windows 10/11.
- .NET 10 SDK.
- Інтернет для першого відновлення NuGet-пакетів.

У PowerShell із кореня репозиторію:

```powershell
dotnet restore .\LEOPARD.slnx
dotnet run --project .\src\LEOPARD\LEOPARD.csproj
```

Збірка без запуску:

```powershell
dotnet build .\LEOPARD.slnx
```

При першому запуску LEOPARD створює схему SQLite у `%LOCALAPPDATA%\LEOPARD\club.sqlite3`. Записи не створюються автоматично. Спочатку відкрийте «Комп’ютери» й додайте інвентар, потім створіть тариф і картки клієнтів. Після цього можна починати сеанси й бронювати слоти. Попередня розробницька база `leopard.db`, якщо вона була, автоматично не видаляється та не підміняє нову базу.

SQLite обрано для автономного запуску на одному адміністративному комп’ютері без окремого сервера. Для спільної роботи кількох робочих місць знадобляться серверна база, API, резервні копії та правила синхронізації.

## Сценарій перевірки під час показу

1. Запустіть застосунок: новий екземпляр не містить вигаданих клієнтів, характеристик ПК, сеансів або бронювань.
2. Додайте комп’ютер зі справжніми характеристиками та зоною клубу.
3. Додайте тариф із чинною ціною й описом.
4. Додайте клієнта з телефоном; повторіть номер у іншому форматі й перевірте відмову дубля.
5. Почніть сеанс, вибравши комп’ютер, клієнта, гру, тариф і тривалість. Перевірте показ характеристик та орієнтовної суми.
6. Перейдіть у «Бронювання», створіть слот для іншого клієнта та спробуйте зарезервувати той самий час на тому самому ПК: перетин має бути відхилено.
7. Подовжте сеанс на 30 хвилин, а потім завершіть його. Перевірте історію, приблизну суму й нарахування балів за повні години.
8. Для сповіщення можна створити короткий сеанс і дочекатися порогу 15 хвилин або змінити тестовий час у локальній БД під час ізольованого ручного тесту.
9. Зменште ширину вікна: бічна панель зникає, а навігація й картки переходять у компактний режим.

## Архітектура

- `Models` — типи домену й картки представлення.
- `Services/ClubRepository` — сховище SQLite, правила конфліктів, історія, сповіщення та бонусні бали.
- `ViewModels` — стан інтерфейсу, фільтри, команди й оновлення таймерів.
- `Views` — Avalonia AXAML та прив’язки до ViewModel. Code-behind лише оновлює компактний стан за шириною вікна.

Використовується **MVVM**. View відображає властивості ViewModel і викликає її команди; ViewModel не керує кнопками напряму та делегує предметні операції репозиторію.

### MVC та MVVM

У **MVC** Model містить стан і правила, View показує результат, а Controller приймає події/запити та обирає, як сформувати відповідь або наступне подання. Це природна схема для HTTP-запитів, маршрутизації та серверного вебзастосунку.

У **MVVM** View має декларативні bindings на властивості й команди ViewModel. Зміни властивостей автоматично оновлюють XAML-подання. Це добре пасує настільним інтерфейсам із XAML, двостороннім введенням та командами.

LEOPARD — desktop-застосунок на Avalonia з MVVM, а не вебсайт і не MVC-застосунок. SQLite-репозиторій є сервісом доступу до даних; ViewModel не містить SQL.

### Порівняння UI-фреймворків

| Фреймворк | Переваги | Відповідність потребам LEOPARD |
|---|---|---|
| Avalonia UI | C#/XAML, desktop для Windows/Linux/macOS, спільний UI-код, можливість окремих mobile targets | Вибрано для Windows desktop і переносимого XAML UI; мобільний вигляд адаптовано, але Android target не налаштований |
| WPF | Зрілий Windows UI, XAML і глибока інтеграція з Windows | Гарний Windows-only варіант, але не відповідає цілі переносимого desktop/mobile-коду |
| WinUI 3 | Нативна сучасна оболонка Windows | Підходить для Windows, але не дає спільної Android цілі |
| .NET MAUI | C#/XAML та спільний проєкт для Android/iOS/macOS/Windows | Сильний вибір для мобільного продукту; потребує platform workloads, яких цей desktop MVP наразі не налаштовує |

Avalonia вибрано через вимогу C#/.NET, XAML, desktop-інтерфейс адміністратора та адаптивні екрани. Зміна ширини вікна показує mobile-style layout, але сама по собі не означає наявність Android APK.

## Реалізовані частини та обмеження

- **Є зараз:** локальний облік інвентарю, клієнтів, тарифів, активних сеансів і бронювань; таймери; внутрішні нагадування; журнал; бали лояльності; мобільний layout.
- **Розрахунок вартості:** оцінка за тарифом і хвилинами. Це не списання та не підтвердження платежу.
- **Характеристики ПК:** адміністратор вводить їх вручну. LEOPARD поки не опитує фізичні комп’ютери.
- **Дані:** нове сховище починається порожнім. Старе `leopard.db` не видаляється; перенесення попередніх локальних даних до `club.sqlite3` не виконується автоматично.
- **Локальність:** дані зберігаються тільки на цьому Windows-профілі; немає багатокористувацького сервера, облікових записів чи синхронізації між комп’ютерами.
- **Інтеграції:** платежі й керування ПК не підключені. Окрема технічна межа інтеграції описана у `docs/PC-AGENT-INTEGRATION.md`; без установленого агента статус фізичного ПК не вигадується.
- **Figma:** підключеного доступу до Figma в середовищі немає; файл і посилання не створювалися. Точний опис дизайну наведено в `docs/DESIGN-SPEC.md`.
