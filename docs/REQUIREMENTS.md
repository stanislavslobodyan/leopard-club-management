# Вимоги та технології LEOPARD

## Функціональні вимоги

| ID | Вимога | Реалізація |
|---|---|---|
| FR-01 | Вести інвентар ПК і характеристики | Додавання ПК, зона, CPU, GPU, RAM, монітор, накопичувач |
| FR-02 | Вести картки клієнтів | Ім’я, телефон, улюблена гра, візити, бали лояльності |
| FR-03 | Вести тарифи | Назва й погодинна ціна |
| FR-04 | Починати сеанс | Вибір вільного ПК, клієнта, гри, тарифу та планової тривалості |
| FR-05 | Керувати активним сеансом | Живий таймер, пошук/фільтр, продовження на 30 хв, завершення |
| FR-06 | Бронювати робочі місця | Майбутні слоти та перевірка перетинів із сеансами/бронюваннями |
| FR-07 | Вести історію та звітну суму | Збережена сума за фактичним часом і тарифом; денний підсумок |
| FR-08 | Нараховувати лояльність | Один бал за кожну повну годину завершеного сеансу |
| FR-09 | Сповіщати про час сеансу | Нагадування за 15 хвилин і після вичерпання планового часу |
| FR-10 | Перевіряти зв’язок із ПК | Опційний PC Agent endpoint, online/offline опитування |
| FR-11 | Приймати й підтверджувати платіж | Не реалізовано: немає каси, термінала, платіжного провайдера або реєстрації оплати |
| FR-12 | Дистанційно керувати ігровими ПК | Не реалізовано: PC Agent відповідає тільки на health-запит |

## Нефункціональні вимоги

| ID | Вимога | Реалізація / обмеження |
|---|---|---|
| NFR-01 | Цільова платформа адміністратора | Windows 10/11, .NET 10 |
| NFR-02 | Локальне збереження | SQLite у `%LOCALAPPDATA%\LEOPARD\club.sqlite3` |
| NFR-03 | Збереження чинних даних при оновленні схеми | SQLite `EnsureColumn` додає нові nullable/defaulted поля під час запуску |
| NFR-04 | Розділення UI та логіки | Avalonia AXAML Views, CommunityToolkit.Mvvm ViewModels, repository/service |
| NFR-05 | Адаптація до вузького вікна | Компактний layout для ширини менше 760 px; Android target не налаштований |
| NFR-06 | Обмеження мережевого агента | HTTP без автентифікації; використовувати лише в довіреній приватній LAN |
| NFR-07 | Багатокористувацький режим | Не реалізовано: база не синхронізується між ПК |
| NFR-08 | Тестування | Перевірка збіркою та ручний сценарій; окремого автоматизованого test project немає |

## Архітектура: MVC та MVVM

У **MVC** Model містить дані та правила, View відображає результат, а Controller приймає дії/запити й координує відповідь. Такий поділ часто застосовують у вебзастосунках із HTTP-маршрутами.

У **MVVM** View прив’язаний (binding) до властивостей і команд ViewModel. ViewModel надає стан екрана й делегує предметну роботу сервісам та сховищу. Це відповідає Avalonia та XAML, де bindings оновлюють інтерфейс при зміні властивостей.

LEOPARD використовує MVVM: SQL та транзакції зберігаються в `ClubRepository`, взаємодії та форматування стану — у ViewModels, розмітка — в AXAML.

| UI-фреймворк | Сильні сторони | Чому обрано / не обрано |
|---|---|---|
| Avalonia UI | C#/XAML, desktop Windows/Linux/macOS, переносимий UI-код | Обрано для .NET desktop-програми та компактного спільного інтерфейсу |
| WPF | Зрілий Windows-only XAML | Підійшов би для суто Windows застосунку; менше переносимості |
| WinUI 3 | Сучасний Windows native UI | Добрий Windows-вибір; не орієнтований на спільний desktop/mobile target |
| .NET MAUI | Спільний C#/XAML проєкт для mobile та desktop | Сильний варіант, якщо першочергові Android/iOS; у цьому проєкті MAUI workloads не налаштовані |
