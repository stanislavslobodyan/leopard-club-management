# LEOPARD PC Agent

## Стан реалізації

У репозиторії є окремий Windows/.NET console agent і клієнт опитування в desktop-застосунку. Agent не запускається автоматично на фізичних клубних ПК: його треба окремо розгорнути на кожній машині й додати адресу до картки комп’ютера. Поки адреса не задана, LEOPARD показує «Агент не налаштовано». Після налаштування показує «Очікує перевірки», а результат — «Агент на зв’язку» або «Агент недоступний».

Перевірка відбувається кожні 20 секунд із таймаутом HTTP 3 секунди. Статус агента окремий від стану облікового сеансу/бронювання: online не означає, що ПК вільний.

## Контракт

Agent слухає TCP `47831` (порт можна перевизначити аргументом) і зараз підтримує тільки:

| Метод | Шлях | Відповідь |
|---|---|---|
| GET | `/api/v1/health` | JSON з ідентифікатором вузла, версією агента, UTC-часом і станом `ready` |

```json
{
  "agentId": "CLUB-PC-01",
  "agentVersion": "1.0.0.0",
  "observedAt": "2026-11-05T12:30:00+00:00",
  "health": "ready"
}
```

Desktop-клієнт вимагає HTTP 200, `health = ready` і непорожній `agentId`. Адреса нормалізується та зберігається у локальному записі комп’ютера. У картці ПК натисніть «Налаштувати агент» і введіть базову адресу, наприклад `http://192.168.1.50:47831`; поле можна очистити, щоб вимкнути перевірку.

## Локальна перевірка

1. У PowerShell з кореня репозиторію запустіть:

   ```powershell
   dotnet run --project .\src\LEOPARD.PcAgent\LEOPARD.PcAgent.csproj
   ```

2. У LEOPARD додайте ПК або відкрийте «Налаштувати агент» для наявного.
3. Вкажіть `http://127.0.0.1:47831` і збережіть адресу.
4. За кілька секунд на картці ПК має з’явитися «Агент на зв’язку».
5. Зупиніть агент через Ctrl+C: після наступного опитування статус стане «Агент недоступний».

Для клубної машини зберіть агент командою:

```powershell
dotnet publish .\src\LEOPARD.PcAgent\LEOPARD.PcAgent.csproj -c Release -r win-x64 --self-contained true
```

Запустіть `LEOPARD.PcAgent.exe` на ПК клубу та внесіть адресу цього комп’ютера у LAN. Щоб агент працював постійно після перезавантаження, його потрібно окремо зареєструвати як Windows-службу або задачу планувальника; це не налаштовується автоматично.

## Безпека та межі

- Agent зараз використовує звичайний HTTP і не має автентифікації. Він відкриває лише мінімальний health-відгук без персональних даних і команд, але мережевий доступ усе одно слід обмежити.
- Використовуйте лише довірену ізольовану LAN. На Windows host firewall обмежте вхідний TCP 47831 IP-адресою адміністративної станції або локальною підмережею; не налаштовуйте port forwarding із публічного інтернету.
- Приклад правила для приватної LAN (запускати від адміністратора на кожному клубному ПК, замінивши діапазон адрес відповідно до мережі):

  ```powershell
  New-NetFirewallRule -DisplayName "LEOPARD PC Agent" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 47831 -RemoteAddress 192.168.1.0/24 -Profile Private
  ```

- Якщо мережа не довірена або виходить за межі локальної підмережі, спершу потрібні TLS, автентифікація, керування секретами й перевірка безпеки протоколу.
- Цей agent не збирає CPU/GPU/RAM, не блокує Windows, не завершує сеанси, не запускає ігри та не керує живленням ПК. Ці можливості не показуються як наявні.
- Фізичні вузли клубу ще не налаштовані в цьому середовищі. До введення їхніх реальних адрес статуси залишаються не налаштованими.
